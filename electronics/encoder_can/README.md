# Энкодер сустава с CAN — опытная ревизия A

Плата для двух магнитных дорожек: STM32G431KBU6, два TMAG5273A2,
TCAN332G и питание 5 В → 3,3 В. Четыре слоя, толщина 0,8 мм.
Датчики расположены на передней стороне над радиусами 23,5 и 29,5 мм.
Один вариант железа для всех суставов; номер узла задаётся прошивкой.

Открыть `encoder_can.kicad_pro` в KiCad 10.0.x. Схема, локальные символы,
посадочные места и таблицы библиотек находятся рядом с проектом.
Программы сборки проверены в официальном контейнере `kicad/kicad:10.0.6`.

## Файлы

- `encoder_can.kicad_sch` — электрическая схема.
- `encoder_can.kicad_pcb` — текущее состояние платы; трассировка сохраняется здесь.
- `design/electrical_spec.json` — компоненты, проверенные выводы и соединения.
- `design/electrical_notes.md` — обоснование выбора, источники и ограничения прототипа.
- `design/prototype_readiness.md` — подтверждённые соединения и незакрытые требования прототипа.
- `design/placements.json`, `mechanics.json` — размещение и контур из механической модели.
- `design/schematic.pdf` — просмотр схемы.
- `manufacturing/BOM.csv` — сгруппированный черновик состава сборки.
- `manufacturing/assembly_components.csv` — состав по обозначениям.
- `manufacturing/assembly_instructions.txt` — изготовление, ориентация и первое включение.

## Обновление модели и трассировка

Все команды ниже выполняются из `electronics/encoder_can`.
`build_board.py` создаёт плату заново и удаляет существующую трассировку:
для обычного редактирования открывайте сохранённую PCB в KiCad.

1. При изменении электрической спецификации: `python3 scripts/build_schematic.py`.
2. Экспортировать свежий список соединений:

   ```sh
   kicad-cli sch export netlist --format kicadxml --output design/netlist.xml encoder_can.kicad_sch
   ```

3. При необходимости заново построить плату: `python3 scripts/build_board.py`.
   Для этой команды нужен Python из среды KiCad с модулем `pcbnew`.
4. Экспортировать DSN: `python3 scripts/route_board.py export` в той же среде.
5. Открыть `design/encoder_can.dsn` во Freerouting 2.5.0 JAR с Java 25,
   выполнить трассировку и сохранить session
   как `design/encoder_can.ses`. Трассировка — отдельный шаг; exporter её не выполняет.
6. Импортировать результат: `python3 scripts/route_board.py import`.
7. Проверить обе стороны, зоны земли, DRC, соответствие схеме и механический зазор.
   Генерация геометрии и завершённая трассировка требуют отдельных проверок.

Пример запуска Python с `pcbnew` в установленном контейнере:

```sh
docker run --rm --platform linux/amd64 --network none \
  -v "$PWD:/work" -w /work --entrypoint python3 \
  kicad/kicad:10.0.6 scripts/build_board.py
```

Для экспорта/импорта DSN замените последнюю команду на
`scripts/route_board.py export` или `scripts/route_board.py import`.
Рабочие ориентации корпусов задаются в `placements.json`;
исправлений формы площадок в DSN не требуется. In1.Cu сохраняется для GND.
Нативная сборка Freerouting 2.5.0 в используемой среде имеет ошибку reflection;
для проверенного процесса используется JAR с Java 25.

## Производственные файлы

Обновить только BOM и инструкции, без Gerber:

```sh
python3 scripts/export_manufacturing.py
```

После завершения трассировки и проверки платы экспортировать пакет:

```sh
python3 scripts/export_manufacturing.py --export --docker
```

При установленном локальном `kicad-cli` убрать `--docker`; нестандартный путь
задаётся через `--kicad-cli /полный/путь/kicad-cli`.
`--export --docker --dry-run` печатает команды и обновляет черновик BOM,
но не запускает проверки и не создаёт производственные файлы.

Exporter сначала выполняет ERC и DRC с проверкой соответствия схеме.
При нарушениях экспорт прекращается; отчёты остаются в `manufacturing/checks`.
При успешной проверке появляются:

- `gerbers/` — четыре слоя меди, две маски, две шелкографии, контур и две пасты.
- `drills/` — Excellon PTH/NPTH в мм, карта и отчёт сверления.
- `encoder_can_fabrication.zip` — Gerber и сверловка для изготовителя PCB.
- `encoder_can_positions.csv` — CPL из самой PCB, обе стороны, мм, штатные углы KiCad.
- `export_manifest.json` — версия KiCad и хеши исходников/результатов.

Ориентир для заказа PCB: **FR-4, 4 слоя, 0,8 мм, ENIG**; конкретный stackup
и допуски согласуются с изготовителем. Нижняя сторона CPL не зеркалируется
дополнительно; ориентацию pin 1 нужно сверить в предварительном просмотре сборщика.

## До заказа монтажа

По умолчанию устанавливается 29 компонентов. R9 120 Ом — DNP;
его ставят только на двух концах общей CAN-шины. J1/J2/TP1 — плоские контакты
платы, отдельных разъёмов или компонентов для них нет.

BOM содержит выбранные микросхемы, но точные складские MPN пассивов и коды
сборщика ещё не заполнены. Наличие заказной конфигурации кварца CL12/ESR≤80 Ом
нужно подтвердить. Замену кварца ESR150 нельзя делать автоматически.
При уточнении закупки изменяйте `electrical_spec.json`, затем пересоздавайте BOM;
ручные изменения сгенерированного CSV будут перезаписаны.

Перед серией необходимы прошивка и проверка малой партии: питание/нагрев,
SWD, запуск кварца, оба I²C, CAN и калибровка магнитных колец по полному обороту.
Файлы платы сами по себе не подтверждают точность абсолютного угла.
Для U1 при R29,3 мм требуется обновлённая крышка с локальным карманом MCU;
старый вариант с одним кольцевым карманом R27…33,7 не подходит.
Подробный список открытых требований — в `design/prototype_readiness.md`.
